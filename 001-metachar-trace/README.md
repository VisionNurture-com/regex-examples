# 001 — パターンがどこで失敗したかを出力する

対応記事: 正規表現とは？図解でわかる基本メタ文字と仕組み

## 動かす

```bash
python3 trace.py 'a.c' 'abbc'          # どこで外れたかを出す
python3 trace.py '^cat' 'my cat'
python3 trace.py 'report\.txt' 'reportXtxt'
python3 anchors.py                      # $ が末尾の改行まで許すかを調べる
bash logfilter.sh                       # 4 記号だけでログを絞り込む
```

## 何が出るか

### trace.py

1. パターンを前から 1 文字ずつ伸ばして、どこで入力に一致しなくなるか
2. 開始位置を 1 つずつずらして、どこから試したか
3. Python がパターンをどう解釈したか（`re.DEBUG` の出力）

`a.c` に `abbc` をかけると「`a.` までは合っていて、その次の要素で外れた」と出ます。
返り値が None であることしか分からない状態から、どこで外れたかが見える状態に変わります。

### anchors.py

`^ABC$` を、末尾に改行が 1 つ残った `"ABC\n"` にかけます。Python は一致し、
JavaScript は一致しません。同じパターンでも実行系で結果が割れることと、
`\Z` を使えば Python でも末尾の改行を拒めることが実測で出ます。

`node` が見つからない環境では JavaScript の行だけを飛ばします。

### logfilter.sh

10 行のサンプルログ（`access.log`）に対し、`example.com` からのアクセスだけを
数えたいという目的を 4 段階で追い込みます。一致件数が 9 → 7 → 5 → 4 と減る過程で、
`.` `\` `^` `$` の 4 記号がそれぞれ何を効かせているかが分かります。

量指定子（`*` `+` など）は入門記事の範囲外のため使わず、複数条件はパイプでつないでいます。

## 必要なもの

Python 3.11 以降、`grep`（BSD / GNU どちらでも動作）
