# 006 — ReDoS の再現と、記法だけで止める

対応記事: 正規表現の実践パターンと ReDoS

## 動かす

```bash
npm ci                                  # 検出ツールと ESLint プラグインを入れる（初回のみ）

python3 bench.py                        # 危険な形を再現し、記法だけで止まることを確かめる
python3 rewrite.py                      # 入れ子を平らに書き換えて止める（記法が使えない環境向け）
node detectors/compare.mjs              # 検出ツール 3 種を実測ラベルと突き合わせる
bash eslint-config/compare.sh           # 設定の有無で検出結果がどう変わるかを並べる
```

`make 006` で `npm ci` を含めて 4 本まとめて実行できます。

実行系を替えたときの差は外部の道具（Go / .NET / Rust）が要るため、別の入口にしてあります。
**見つからない実行系は行ごと飛ばす**ので、Python と Node だけの環境でも動きます。

```bash
bash engines/compare.sh   # make 006-engines と同じ
```

## 何が出るか

### bench.py

`(a+)+$` に対して `a` を n 個並べた入力を与えたときの実行時間と、
アトミックグループ・所有量指定子・安全な書き方の 3 つを並べた比較です。

危険な形は入力が少し伸びるだけで時間が跳ね上がりますが、
アトミックグループを 1 つ足すだけで一定に保たれます。

### rewrite.py

アトミックグループも所有量指定子も無い環境（JavaScript など）で残る手は、
パターンそのものの書き換えです。ただし書き換えは判定を変えかねません。

短い文字列を総当たりして**書き換えの前後で判定が一致するか**を確かめてから、
実行時間を比べます。最後に「入力長の上限」を決めたときの最悪の待ち時間も出します。

3 つの書き換え案のうち、判定が一致するのは 1 つだけです。

### detectors/compare.mjs

safe-regex・redos-detector・recheck の 3 つに同じ 13 パターンをかけ、
見逃しと誤検出を数えます。

**正解ラベルはツールの主張ではなく実測で決めています。** 攻撃文字列を 10 文字から
26 文字まで伸ばし、4 文字あたりの増加率が 3 倍以上のものを危険としました。

> マイクロ秒で終わるパターンは他の処理の影響を受けやすく、空いていない環境では
> 安全な形が危険側に振れることがあります。判定が変わったら測り直してください。

### eslint-config/compare.sh

同じファイルを 3 通りの設定（ルールなし / 1 ルールだけ / プラグインの推奨）で検査し、
終了コードと検出内容を並べます。

ESLint の終了コードは **0 = 指摘なし / 1 = 指摘あり / 2 = 設定・依存のエラー**です。
2 を「検出あり」と数えると環境の不備が測定結果に化けるため、区別して表示します。

### engines/compare.sh

同じ `(a+)+$` に同じ入力を与え、実行系だけを替えて測ります。
bench.py が「同じ実行系で書き方を替える」のに対し、こちらは「同じ書き方で実行系を替える」軸です。

戻りながら探す方式（Python / JavaScript / .NET 既定）と、戻らない方式
（Go / Rust / .NET `NonBacktracking`）で桁が変わります。

## 注意

危険な形は入力長を小さく保っています。本番のコードには持ち込まないでください。

## 必要なもの

Python 3.11 以降、Node.js、npm。`engines/compare.sh` は任意で Go / .NET / Rust を使います。
